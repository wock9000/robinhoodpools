[Pancake's official V3 address list](https://developer.pancakeswap.finance/contracts/v3/addresses) does not list Robinhood Chain; its verified [SmartRouter source](https://robinhoodchain.blockscout.com/api/v2/smart-contracts/0x13f4EA83D0bd40E75C8222255bc855a974568Dd4) on chain is the authority. The verified `factoryV3()` returns the Pancake factory; `WETH9()` returns `0x0bd7d308f8e1639fab988df18a8011f41eacad73`. Its NFPM is `0x46a15b0b27311cedf172ab29e4f4766fbe7f4364`. Giga is GigaDEX's **Apex CL**, a Pancake-derived concentrated-liquidity fork, not a Uniswap pool; verified `CLFactory.sol`, `SwapRouter.sol`, and [NFPM](https://robinhoodchain.blockscout.com/api/v2/smart-contracts/0xa79f5775b0b49e51202c48ddf03f380faa96f641) establish its identity (`Giga Positions`, `GIGA-POS`). Giga's router constructor contains its own CL factory and the canonical WETH address. A [successful routed swap](https://robinhoodchain.blockscout.com/tx/0x90af31b573be811e76c64a29f76a1c990788ce309df871da8d1d5c78a0733dcf) calls its `exactInputSingle` selector. [up Finance docs](https://up33.xyz/docs/overview) describe the Slipstream-style CL deployment; Blockscout identifies its factory as `CLFactory`, and its verified SwapRouter's immutable `factory()` returns precisely `0x1ac9db4a2608ba45d6127b1737949b51bb54b7f3`; `WETH9()` returns canonical WETH. The local market's `pools` table contains its factory and real USDG/token pools, e.g. `0x18a5af4e442f8be68968cc1f00d537f8af2d12cd` at spacing 60. `getPool(USDG,0xd0601ce157db5bdc3162bbac2a2c8af5320d9eec,60)` returns that address; `getPool(WETH,USDG,10)` returns the liquid bridge `0x16679e2ac1a798865ecf1c1639e67693ddb1c220`. These are up Finance contracts, **not** Raphael's distinct Slipstream deployment.

For each external V3 router, the entire gross swap output first enters the router, then its `sweepTokenWithFee` sends `floor(gross_output * 75 / 10000)` to the configured recipient and the remainder to the trader. The wallet approves the router, not Permit2; the existing UR path retains its Permit2/input-fee behavior. This changes the denomination of the fee for external-router buys (output token) because these already-deployed routers cannot atomically take an exact input-token fee from the wallet and then spend the remaining input without an additional trusted contract. Both the quote and receipt account for the **actual** fee currency and exact wei amount. Routes bridge only between pools of the same factory; a mixed-factory path would require a separate executor and is refused. An indexed factory without a deployed verified fee-capable router remains unsupported, with the factory named in the `no_route` refusal. No contract is deployed.

Fork proof: `PYTHONPATH=src .venv/bin/python -m pytest -q tests/test_tx_fork.py -k protocol_router` exercised direct and two-hop buys and sells for Pancake, Giga, and up Finance: `6 passed, 18 deselected`. Tests reconcile the trader, pool, fee recipient and quote exactly on mined receipts; the fork uses native code and immutable getters on chain 4663.
